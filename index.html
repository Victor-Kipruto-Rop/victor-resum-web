Learning & Project Experience

PesaGuard — FinTech Reconciliation Platform

Independent Product · Live Pilot

2026 – Ongoing

What I built

A real-time M-Pesa reconciliation and anomaly-detection platform: a Flask backend that ingests Safaricom Daraja webhook events, an idempotency-guarded reconciliation engine, a PostgreSQL data layer, and a Next.js 14 admin dashboard for monitoring transactions, match rates, and open anomalies.

What problem I solved

Kenyan SACCOs, e-commerce operators, and small fintechs had no reliable way to reconcile M-Pesa payments against their own ledgers — it was typically a manual, end-of-day spreadsheet exercise. Worse, Safaricom retries webhook deliveries, so duplicate transactions were a certainty, not an edge case, with nothing in place to catch them.

Technologies

Flask Python Next.js PostgreSQL Daraja API

Impact

Live in production with one pilot customer processing real M-Pesa transactions. Shipped webhook idempotency — the highest-priority risk in the system — verified end-to-end across the reconciliation engine, so a retried or duplicate webhook can never be double-counted. Also produced a target-state architecture spec scoping the platform to 100M transactions/day.
